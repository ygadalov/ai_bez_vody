# Промпты проекта «Ежемесячная презентация» — по шагам

Промпты из урока 9 целиком, чтобы их было удобно копировать. Порядок работы:
шаг 0 — отдельный чат для спецификации; шаги 1–6 — чат (или несколько чатов), где пишется скрипт.
К каждому промпту шагов 1–6 прикладывайте `spec.md` и текущую версию `build_presentation.py`
(на шаге 1 скрипта ещё нет). Если чат стал длинным и модель путается — начните новый с этими двумя файлами.

Реальные цифры модели не нужны: давайте структуру файлов и выдуманный пример.

---

## Шаг 0. Спецификация (spec.md)

```
Я веду ежемесячную презентацию для руководства и хочу автоматизировать
её сборку скриптом на Python. Сначала нужна спецификация — точное
описание задачи, по которому потом напишут скрипт.

Структура презентации: [список слайдов: № | название | что на нём —
таблица, график или текст; или файл презентации прошлого месяца]
Исходники: [файлы, листы, заголовки колонок, подписи строк;
цифры замените выдуманными]

Сначала задай мне до 10 вопросов о том, чего не хватает: откуда
каждая цифра, как её считать и округлять, что делать при ошибках
в данных, откуда берутся тексты.
После моих ответов составь спецификацию в формате Markdown
с разделами: 1) цель и границы; 2) входные данные (таблица: файл |
лист | колонки | строки); 3) проверки входа; 4) карта «слайд →
источник → правило» (таблица); 5) шаблон; 6) приёмка.
Ничего не придумывай: где не знаешь — пиши «УТОЧНИТЬ».
```

Дальше: ответить на вопросы → выверить черновик с ручной презентацией, закрыть все «УТОЧНИТЬ» →
сохранить как `spec.md` (обычный текстовый файл; подойдёт и `spec.txt`).

## Шаг 1. Чтение и проверка исходников

```
Я финансист, не программист. Пишем скрипт на Python по шагам
по приложенной спецификации spec.md. Сейчас шаг 1: чтение
и проверка исходников.

Пример листа «Сводка» (числа выдуманы):
Направление | План выручки, млн руб. | Факт выручки, млн руб. | EBITDA, млн руб.
Флот | 500 | 512 | 159  …  Итого | 1620 | 1605 | 473

Что сделать: прочитать все листы из раздела 2 спецификации, строки
искать по подписи в первой колонке. Выполнить все проверки из
раздела 3. Если проверка не прошла — не падать с ошибкой Python,
а вывести понятный список проблем по-русски и остановиться.
Если всё в порядке — пока просто напечатать прочитанные цифры.
Библиотека: openpyxl. Добавь короткие комментарии по-русски.
```

**Проверить:** цифры в консоли совпадают с Excel; на копии файла с переименованной колонкой — понятная ошибка.

## Шаги 2–6: общее начало и конец

Каждый из промптов ниже начинается строкой
`Вот spec.md и текущая версия build_presentation.py.`
и заканчивается строкой
`Остальные части скрипта не меняй. Покажи файл целиком.`

## Шаг 2. Расчёт показателей

```
Вот spec.md и текущая версия build_presentation.py.
Шаг 2: посчитай показатели по правилам из карты (раздел 4
спецификации): исполнение плана, рентабельность EBITDA,
Долг/EBITDA и статус ковенанта, изменения по направлениям.
Числа форматируй, как в разделе 4: «1 605», «29,5», минус «−».
Расчёт — отдельной функцией. Пока только напечатай результат,
презентацию не трогай.
Остальные части скрипта не меняй. Покажи файл целиком.
```

**Проверить:** 2–3 показателя пересчитать в Excel вручную.

## Шаг 3. Один слайд — образец

```
Вот spec.md и текущая версия build_presentation.py.
Шаг 3: заполни один слайд — № 6 «Флот». Шаблон template.pptx
приложен: таблица на слайде называется «Таблица_Флот», в её
ячейках стоят прочерки «—», под таблицей метка {{комментарий_Флот}}.
Замени прочерки числами, сохранив оформление ячеек; метку —
комментарием из kommentarii.xlsx дословно, с автором.
Сохрани результат в out/Отчёт_ГГГГ-ММ.pptx (месяц — из имени папки).
Цвета и шрифты в коде не задавай. Библиотека: python-pptx.
Остальные части скрипта не меняй. Покажи файл целиком.
```

**Проверить:** слайд выглядит как в ручной версии, цифры на месте, оформление не сбилось.

## Шаг 4. Остальные слайды «по образцу»

```
Вот spec.md и текущая версия build_presentation.py.
Шаг 4: слайд 6 «Флот» уже заполняется правильно. По его образцу
заполни таблицы слайдов 2, 5, 7, 8, 9 и все метки {{…}} по карте
из раздела 4 спецификации. Используй уже написанные функции
чтения, проверки и форматирования чисел, новых не дублируй.
Остальные части скрипта не меняй. Покажи файл целиком.
```

**Проверить:** во всей презентации не осталось ни одной метки `{{…}}` и ни одного прочерка.

## Шаг 5. Графики

```
Вот spec.md и текущая версия build_presentation.py.
Шаг 5: в шаблоне два графика. «График_план_факт» — столбцы «План»
и «Факт» по трём направлениям; «График_динамика» — линии по месяцам
для трёх направлений, число месяцев берётся из листа «Динамика»
и растёт каждый месяц. Подставь данные через замену данных
графика, чтобы оформление рядов из шаблона сохранилось.
Остальные части скрипта не меняй. Покажи файл целиком.
```

**Проверить:** на графике динамики столько месяцев, сколько в Excel; цвета рядов — как в шаблоне.

## Шаг 6. Служебный слайд и итог

```
Вот spec.md и текущая версия build_presentation.py.
Шаг 6: заполни метку {{контроль}} списком: какие файлы прочитаны,
контрольные суммы (план, факт и EBITDA итого), Долг/EBITDA,
напоминание «удалить слайд перед отправкой». После сохранения
выведи путь к файлу и контрольные суммы. Если в презентации
остались незаполненные метки {{…}} — выведи предупреждение.
Остальные части скрипта не меняй. Покажи файл целиком.
```

**Проверить:** контрольные суммы на служебном слайде совпадают с итогами в Excel.
